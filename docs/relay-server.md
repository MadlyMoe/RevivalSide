# RevivalSide Internet Relay

The RevivalSide relay lets both players use Friendly Battle over the public internet without exposing TCP `22000`, HTTP `8088`, a home IP address, or the User Manager. Both launchers connect outward over HTTPS/WebSocket TLS. The hosting player's local listener and CombatHost remain authoritative; the VPS only authenticates room traffic and forwards encrypted tunnel frames.

## What the contributor needs

- An Ubuntu 24.04 or Debian 12 VPS with a public IP address.
- A DNS name such as `relay.example.com` pointed at that VPS.
- TCP `22` open for SSH setup and TCP `443` open for the relay. If a different relay port is selected, open that port instead.
- An SSH user that accepts key authentication and can run `sudo` without a password, or a root SSH account. Interactive password prompts are deliberately not supported by one-click setup.
- The SSH private key on the computer running the launcher, or the key loaded into Windows `ssh-agent`.
- The VPS SSH host-key fingerprint copied through the provider console. On the VPS, run `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256` and enter its `SHA256:...` value. The launcher refuses to upload files if this pin does not match.
- A PEM TLS certificate and unencrypted PEM private key whose certificate covers the relay DNS name. Keep the TLS private key private.
- Windows OpenSSH Client (`ssh.exe` and `scp.exe`) on the setup computer.
- Outbound internet access from the VPS and both players' computers.

The VPS does **not** need the CounterSide client, RevivalSide user database, gameplay assets, Node.js, or the .NET runtime. The launcher uploads a self-contained Linux relay binary.

## One-click setup

1. Open **Settings > PvP** in the RevivalSide launcher.
2. Choose **Host a match** and click **Generate credentials**.
3. Fill in the SSH host, port, user, private-key path, pinned SSH host-key fingerprint, public relay hostname, HTTPS port, TLS certificate, TLS private key, and install path.
4. Click **Deploy, start, and verify relay**.
5. The launcher uploads the relay over SSH, creates a dedicated unprivileged `revivalside-relay` system user, installs a locked-down systemd service, starts it, and checks `https://relay.example.com/health` using the normal operating-system trust store.

Setup fails closed if SSH host verification, passwordless `sudo`, TLS validation, service startup, or the health check fails. It never disables certificate validation.

## What to share with players

Share only:

- The relay URL, for example `https://relay.example.com`.
- The relay access secret generated by the launcher.
- The eight-character in-game room code after the host creates a room.

Do not share the SSH private key, VPS login, TLS private key, or host relay ID. A guest selects **Join a host**, enters the relay URL and access secret, starts their listener, then joins through the normal Friendly Battle code UI.

Rotate the relay secret and redeploy if it is disclosed outside the intended group. Firewall the VPS so only SSH and the relay HTTPS port are reachable, keep the OS patched, and restrict SSH by source IP when practical.
